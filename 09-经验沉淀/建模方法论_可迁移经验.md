# A 通用数学建模经验

**经验名称**：双目标冲突的 ε-约束扫描
**适用场景**：两目标互相冲突、权重无法论证、需展示全部最优可能时。
**触发信号**："既要 A 又要 B"且同抢一个资源；加权权重怎么定都心虚。
**核心思路**：不合成单目标；把一目标降为约束（≥ε）逐点扫描，得完整 Pareto 前沿，再按规则挑档位方案。
**操作步骤**：1) 定两目标方向与量纲；2) 先写单目标模型；3) ε 等距扫描、逐点精确求解（LP/MILP）；4) 去重得非支配前沿；5) 取两端点 + 中段均衡点成三档。
**所需工具**：精确求解器；扫描与去重脚本。
**验证方式**：前沿点互不支配；两端点等于各自单目标极值；加密扫描不退化。
**常见坑**：加权和漏非凸段；步长过粗误判"点少"；未先检查同向（同向应合并为单目标）。
**不适用边界**：目标 ≥3 换多目标进化算法；权重可信时直接加权。
**本次证据**：扫出完整取舍前沿；极端情景下两目标转为"同向"。

**经验名称**：等价最优解治理（简并 + 确定性化）
**适用场景**：存在参数完全对称的决策单元时。
**触发信号**：多次求解目标值相同但方案不同；解出现"任选其一"的碎片分配。
**核心思路**：这是简并（多解等价）；须识别对称性并施加确定性规则；多脚本时系数由单一函数生成（单源）。
**操作步骤**：1) 找"效率严格相等"的候选群；2) 目标叠加极小字典序权重（λ≪真实差异）；3) 或报告层定规则（优先整块/编号）；4) 声明规则不影响目标值。
**所需工具**：可控目标函数的求解接口；一致性回归脚本。
**验证方式**：重复运行输出逐位一致；打乱编号后解随规则而变。
**常见坑**：误判"不稳定"；两处精度不一（舍入 vs 全精度）致代表解漂移；λ 过大改变真实最优。
**不适用边界**：差异真实存在时不强行唯一化，改报敏感性。
**本次证据**：脚本间"舍入 vs 全精度"选出不同代表解，统一后消失。

**经验名称**：不确定性的三层检验
**适用场景**：模型含经验参数、结论需交付他人时。
**触发信号**：参数来自文献区间、无实测；会被问"结论稳不稳"。
**核心思路**：三层各答一问——哪个参数最要命、特定世界状态行不行、综合不确定性下的概率与结构。
**操作步骤**：1) 列参数与区间；2) 单因素**双向**扰动，溯源非对称（阈值/截断/饱和）；3) 情景：常规谱系 + 真实极端事件；4) 联合抽样重解，报目标分布与"结构频率"。
**所需工具**：参数化重解管线；抽样统计。
**验证方式**：敏感方向合理论；高频结构与解析排序互证；极端情景重优化不劣于固定方案。
**常见坑**：只做一层；区间不声明；只看均值不看结构；把不对称当 bug。
**不适用边界**：参数强相关时用相关抽样；高成本模型先做代理。
**本次证据**：三层各出发现——非对称阈值、结构反转、首选单元高频稳定。

**经验名称**：结构切换的临界值指标
**适用场景**：资源分配中"先投谁、投多少轮到下一类"是核心决策时。
**触发信号**：最优解长期只用一类单元；反复被问"何时轮到另一类"。
**核心思路**：定义"次要类首次进入最优解的最小资源量"，扫描资源得临界值，再考察其随参数的迁移规律。
**操作步骤**：1) 给结构变化下可复现定义（写清阈值，如 >0.1%）；2) 步长扫描资源上限并检测；3) 记录首个达标值；4) 扰动参数看迁移规律。
**所需工具**：快速重解脚本；记录表。
**验证方式**：临界前后各复解一次；细步长复核。
**常见坑**：判据含糊（"进入前沿"≠"进入某最优解"）；步长过粗；只报值不报迁移。
**不适用边界**：解跳跃剧烈时改报区间。
**本次证据**：临界值 ≈400 万，随单价线性缩放、对两类参数不敏感。

# B 领域/题型经验

**经验名称**：单位效益表 + 可行集先行
**适用场景**：有限预算在多个候选单元间分配（"花哪最值"）。
**触发信号**：要选"改哪些、各做什么"。
**核心思路**：先建"单元×选项"效果-成本表，**只在可行集内**排单位效益，再进求解器；排序与最优解互印证。
**操作步骤**：1) 全量算效果与成本；2) 依规范/物理剔除不可行并标注；3) 可行集算单位效益并分级；4) 建模求最优；5) 核对投向落在高效益单元。
**所需工具**：系数表脚本；LP/MILP；分级图。
**验证方式**：投向与分级一致；高效益被跳过须能解释（预算顺序/互斥）。
**常见坑**：在不可行组合上比效益；只看绝对量不看单位成本；先求最优后过滤可行性（错序）。
**不适用边界**：单元间强交互时线性可加不成立。
**本次证据**：分级与投向完全一致；提前识别一例"假高效"不可行组合。

**经验名称**：常规谱系 + 真实极端事件双情景
**适用场景**：风险类问题的稳健性论证。
**触发信号**：只有规整重现期情景，从未用真实极端事件压测。
**核心思路**：常规情景看趋势；必用有记录的真实极端事件压测，并做"固定方案 vs 重优化"对照——结构反转常只在此显现。
**操作步骤**：1) 建常规情景谱系；2) 选真实极端事件（注来源、声明近似口径）；3) 每情景做固定评估 + 重优化；4) 对比目标排序与结构变化。
**所需工具**：情景重解；极端事件公开记录。
**验证方式**：重优化不劣于固定；总量不超物理上限。
**常见坑**：极端情景只报"收益变差"；口径不声明；漏重优化对照。
**不适用边界**：极端与常规机制不同（地震 vs 降雨）应换模型。
**本次证据**：极端情景下两目标由权衡转同向，改变推荐措施——最高价值结论。

# C AI/工具使用技巧

**经验名称**：生成物验收（渲染 + 自查）
**适用场景**：AI 生成的图/PDF/Office 交付物。
**触发信号**：脚本成功但交付物从未被真正打开看过。
**核心思路**：程序成功≠视觉正确；交付前主动"找麻烦"（数字三方一致、口径复核、估计值实算）。
**操作步骤**：1) 逐张逐页目检（缺字/遮挡/裁切/比例）；2) 文档做结构校验；3) 列数字引用点清单核对；4) "约"字全部实算；5) 修正留痕。
**所需工具**：图片查看；文档解析；全局检索。
**验证方式**：每图每页有已检记录；修正记录作为信用证据。
**常见坑**：只信运行日志；字体未嵌入不查；估计值留进终稿。
**不适用边界**：数据文件改程序化校验；草稿不必全套。
**本次证据**：多轮图件修正；揪出公式误匹配、副标题误入目录、两处数字口径。

**经验名称**：环境兜底与过程留痕
**适用场景**：环境受限（编码/字体/网络/依赖）且需过程材料。
**触发信号**：编码报错、缺字方框、下载失败、缺包；需要过程证据。
**核心思路**：每类限制预置兜底（脚本内建 fallback）；过程记录即写即存，失败与修正如实留痕。
**操作步骤**：1) 首日探测环境；2) 统一编码、字体多候选、网络重试；3) 关键渲染加 try-fallback；4) 每步即记日志（任务/过程/问题/反思/用时）；5) 汇总版脚本生成（索引手维 + 全文拼接）。
**所需工具**：编码片段；字体候选；重试模式；日志模板 + 汇总脚本。
**验证方式**：故意触发失败验证退化路径；任一数字可从日志回溯。
**常见坑**：只修一次不入规范；兜底输出不声明；日志事后补写致失真。
**不适用边界**：生产环境应修根因；小实验可记要点。
**本次证据**：四类环境问题零中断；日志十余条一键成册。

# 附一、决策树

```
0 定性：帮人决策？否→报告；是→配置/连续/评价/预测
1 配置：系数表(仅可行集)→单位效益分级→目标数(1→LP/MILP；2→ε扫描→Pareto→三档)→对称?→tie-breaker
2 参数：公开数据记来源｜文献取中值+区间(必做不确定性)｜自采写口径；缺来源→假设+敏感性
3 求解前：写全数学形式；可行性先行；数据单源
4 求解后：双向扰动→常规+真实极端→联合抽样(报结构频率)；同向/反转→深挖；多解→唯一化
5 交付前：解析复算｜图件目检｜三方一致｜清"约"字｜日志同步
6 全程：单源｜兜底｜日志即写即存
```

# 附二、检查清单

**定义**：□决策者与问题 □子问题可验证 □输出形式约定
**数据**：□参数有来源 □参数带区间 □精度单源 □异常值说明
**建模**：□假设含违反影响 □可行性先行 □对称性检查 □形式完整
**求解**：□精确方法 □重复一致 □量级守恒
**检验**：□双向扰动 □常规+极端（重优化对照）□结构频率 □解析复算 □反转已解释
**交付**：□图件目检 □结构校验 □数字三方一致 □局限声明 □日志可回溯
